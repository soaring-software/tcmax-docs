Introduction​

Database Connection Profiles are used to connect a subscription to a TCMax Database. Profiles can be reused across multiple subscriptions. All sensitive Data within the Database Connection Profile is encrypted before being saved to the Administration Database.

Name​

A Database Connection Profile Name is a unique value used to identify the connection.

Connection Strings​

Each connection string should be configured with the same server and Database name but use different user credentials. Below details out the required user permissions for each connection.

Default Connection String​

A SQL connection string used for read and write transactions.

  • Required SQL Permissions (Db Role Memberships): db_datareader and db_datawriter.
  • Additional Grants: This user requires Execute permissions on User Defined Table Type dbo.KeyValueTable and on schema cdo to allow execution of stored procedures.
    • Example Script: Use this script to grant your default connection user the additional permissions required. Replace [USER] with the name of your default user.

-- KeyValueTable is a user-defined table type and is used as a parameter in some functions/procedures.
GRANT EXECUTE ON TYPE::dbo.KeyValueTable TO [USER];

-- The cdo schema is used to group stored procedures that need executed when using the default connection.
GRANT EXECUTE ON SCHEMA::cdo TO [USER];

Admin Connection String​

A SQL connection string used for DDL commands (Create, Alter, Drop, Truncate) and executing stored procedures. We use this connection string when running updates and performing maintenance.

  • Required SQL Permissions (Database Role Memberships): db_owner.

Read-Only Connection String​

A SQL connection used for read only transactions. This connection will be used when designing or viewing reports, chart Data etc.

  • Required SQL Permissions (Database Role Memberships): db_datareader.

Load Connection Details from Vault​

An option that enables pulling connection strings from Vault (We currently support HashiCorp and Microsoft Azure vault services) by using the connection string values as keys. This option is for users that want to pull connection strings from vault instead of storing the raw values in our Database.

Generating a Database​

When a Database Connection Profile is saved we will attempt to use the Admin Connection String to create a Database and generate all tables, functions, procedures etc. If the Database already exists then we will try to apply updates to it. If we fail to connect to a Database OR the user defined in the connection does not have the appropriate permissions the Subscription Manager will display an icon to alert the user. The Database Connection Profile can be updated and will attempt to apply all updates upon save. Database Connection Profiles cannot be linked to a subscription until it has successfully connected to a Database and completely ran updates.

Example Connection String​

Server=server_name;Database=database_name;User ID=user_name;Password=password;MultipleActiveResultSets=false;TrustServerCertificate=true;
