HTTP Caching

HTTP Headers​

Cache-Control​

The Cache-Control header will define when or how a response should be cached and for how long.

Cache-Control: Public​

The public cache indicates that the resource is stored and can be accessible to everyone who requests it.

Cache-Control: Private​

The private cache indicates that the resource is stored on an individual client, for example a local browser.

Cache-Control: Max-Age​

Max-Age signifies the amount of time it takes for a cached copy of a resource to expire. The Max-Age by default is assigned to zero because we want individuals to recheck the Server to make sure the data is still appearing correct and current.

Max-Age Example​

Cache-Control: max-age=86400

The example provided above will indicate that the cached resource is good for 86,400 seconds therefore equivalent to one day.

Cache Control: S-Maxage​

S-Maxage signifies the amount of time the cached copy of a resource is good for, this is specific to shared caches. S-Maxage is similar to Max-Age.

S-Maxage Example​

Cache-Control: s-maxage=86400

The example provided above will indicate that the cached resource is good for 86,400 seconds therefore equivalent to one day.

Cache Control: No-Store​

No-Store indicates that no cache is allowed to store the data whether it is a private or shared connection.

Cache Control: No-Cache​

No-Cache identifies that caches can be stored, but before each use the Server must revalidate the resource.

Vary​

The Vary header will determine future requests. Vary will allow cached material to be returned if that information is in the correct format, otherwise it will request a fresh response from the Server.

Expires​

The Expires header will contain the date/time after which the cache is considered expired.

note

If there is a Cache-Control header with max-age or s-maxage, the Expires header will be ignored

Last-Modified​

The Last-Modified header sends a request to the Server to determine when the resource was last modified. The request will provide a date and time. This header is utilized to determine if the resource is the same as the previously stored resource.

Conditional 'GET' and 'HEAD'​

If-None-Match​

The If-None-Match header is used to make the request conditional. This header utilizes ETags to verify that the cached resource is fresh and not out of date. If the ETag does not match the cached resource, you will see a Status Code of 200 'OK' with the updated resource. If the ETag does match the cached resource, you will see a Status Code of 304 'Not Modified', as nothing has changed within the cached resource.

If-Modified-Since​

The If-Modified-Since header indicates that if the requested resource has been modified since the given date then a Status Code of 200 'OK' will be returned. If the resource has not been modified since the given date then a Status Code of 304 'Not Modified' will be returned.

Conditional 'PUT', 'PATCH', and 'DELETE'​

If-Match​

The If-Match header is utilized to make the request conditional. This header utilizes 'row version' to verify that the cached resource is fresh and not out of date. If the request matches one of the listed conditional ETags then the Server will process the request. If the request does not match one of the listed ETags then the Status Code 412 'Precondition Failed' is returned and the request will not be processed.
