Import/Export Records

The Import/Export screen allows a user to populate the current TCMax® Database with Data from another Version 9 Database, an Excel spreadsheet, or from a Version 8 TCMax® Database. To access this feature the user must have a valid User Id and Password and have the Access Import/Export permission in User Options.

Version 9 to 9 Copy​

The Version 9 to 9 Copy tab allows for you to copy Data from one Version 9 TCMax® Database to another Version 9 TCMax® Database. Set the source Database by clicking on the Set Source button and set the destination by clicking on the Set Destination button and then provide the appropriate information in the Connection Properties window that appears.

Provide a Server Name, Authentication Information, and the Database in which the Data is stored for both the source and destination databases.

The copy can be done for all shop codes or for a specific shop code by selecting the appropriate shop code option(s) from the Shop Code Selection drop down box.

Copy Options​

There are several options that dictate how Data will be copied from the source to destination Databases.

Copy All Users From Source: This option, when enabled, will force all users in the source Database to be copied to the destination. When not enabled, only users assigned to your selected site and users who have not been assigned a site will be copied over.

For conflicts, Overwrite Destination Data: This option will overwrite any Data in the destination Database that has the same unique constraints (Shop Code and Barcode Id) as an item in the source.

Update Previously Copied Data: This option updates Data that has already been copied from the selected source to the selected destination. This Data is identified by the ‘SyncId’ applied to the item in the TCMax® Database.

Table Exclusions: These tables can be skipped during the copy the process. Event Log is excluded by default.

Once you have your source and destination databases set and your shop code(s) and options selected you can click the Start Copy button to copy Data from the source to destination. The Copy Event Logs button allows the user to copy the event logs independently if they were excluded from the initial data copy. The Event Log table can be quite vast and separating the movement of data allows for a more efficient use of available computing resources and improved performance during this operation.

During the Copy process, you will see several progress bars appear in the Copy Status section. If there are any errors during the copy you will be notified there as well.

info

Regardless of how you have brought new Data into your system, if you did not import information into an already existing/selected shop code you will need to select the newly imported shop code from the Settings > Sites and Shops screen to have visibility of the items.

Excel Import​

The Excel Import tab is used to import well formatted Excel spreadsheets of information into TCMax®. Using Excel spreadsheets, you can import Items, Users, Item Inspections, and User Certifications.

To load a spreadsheet for import, click the Load Spreadsheet button which will open a Windows Explorer window that you will use to navigate to and select the spreadsheet. Once you have selected the spreadsheet, the Data from the sheet will be displayed in the grid of this tab.

Review the Data in this grid and make any changes necessary prior to import. The text section in the bottom left hand corner of this screen will provide more information as to why specific pieces of information may not be imported into TCMax.

When you are ready to import the Data, click the Import button. When the import has finished the results will be displayed in the grid. If a field is highlighted in red then the Item was not able to be imported, the reason for which is found in the Result field of the grid. Make sure you check the results to ensure the items were imported.

tip

The spreadsheet import is limited to importing up to 10,000 records at a time.

You can also create template spreadsheets for Items, Item Inspections, Users, and User Certifications by selecting the template you would like to create from the dropdown menu in the Create Spreadsheet Template area and clicking the Create Spreadsheet button. When using the template you created, do not delete any of the columns, as TCMax® needs those to read the Data properly.

info

Regardless of how you have brought new Data into your system, if you did not import information into an already existing/selected shop code you will need to select the newly imported shop code from the Settings > Sites and Shops screen to have visibility of the items.

Migrations​

The Migrations tab allows you to bring Data from Version 8 of TCMax® to Version 9 of TCMax®. This function can migrate Data from both SQL Server and Microsoft® Access Databases.

Migrating from Microsoft® Access

Migrating from Microsoft® Access is no longer an option in Version 9.8.7853 and higher of TCMax®. If you do not see this option available and are trying to migrate, contact our Customer Support Center (419) 442-7676 for additional assistance.

Migrate from SQL Server​

info

When performing an 8 to 9 Migration, we require that the Source and Destination Database be on the same Server.

If your Version 8 Data is in a Microsoft SQL Server® Database, select the SQL Server radio button and then click the Set Source button which will bring up a Connections Properties window.

Enter the information for your Server, log in method, and Database. Click the Test Connection button and if it says “Test connection succeeded” you can click the OK button to proceed. If it gives any other result than “Test connection succeeded,” take note of the error indicated and correct the connection information.

Click the Set Destination button and follow the same steps, except in this case you will enter the destination Server’s information. The Database you are currently connected to is selected by default.

Step One - Verify Source Database: To verify that your source Database is up to date and all datatypes are correct you will need to click the Verify Source Database button. This step is not optional and must be completed before progressing to step two.

Step Two - Sync Data: At this point you can click the Sync Data button to move the Data into your destination Microsoft SQL Server® Database. Once this button is clicked, TCMax® will ask if tool chits were used in the previous version of TCMax®. If tool chits were entered in TCMax® Version 8, click yes, otherwise click no.

During the sync, information will appear on the screen letting you know what step of the process you are on.

After the sync is complete, you will be prompted with the Migrate Special Options Data screen which you can read more about below.

Step Three (Optional): You can remove any old Database objects that will no longer be used by TCMax® by clicking the Remove Old Data button.

Migrate from Microsoft® Access​

Migrating from Microsoft® Access

Migrating from Microsoft® Access is no longer an option in Version 9.8.7853 and higher of TCMax®. If you do not see this option available and are trying to migrate, contact our Customer Support Center (419) 442-7676 for additional assistance.

If you are using a Microsoft® Access Database select the Microsoft® Access radio button and then click the Browse button which will bring up a Windows Explorer window that can be used to navigate to your Microsoft® Access Database. Find and select your Microsoft® Access Database and click the Open button on the Explorer window. This will put the file path in the Source Database area. Click the Set Destination button to set your destination.

After you have chosen your Microsoft® Access Database and your destination SQL Database you would proceed to Step One: Transfer Access Database to SQL Server. This process requires you to have SQL Server Migration Assistant (SSMA) installed on your computer. This is part of the complete TCMax® Version 9.X installation but can also be installed separately by going to Microsoft’s website and downloading the installer. A temporary copy of your Database is made, and that copy is the one that is interacted with, so no changes will be made to your Access Database. This process also requires some form of the Microsoft® Access Database Engine which can also be downloaded and installed by going to Microsoft’s website.

Transfer Access Database to SQL Server​

Once you click the Transfer Access Database button, TCMax® will launch a command window (below) which will show text explaining all of the things it’s doing but you will need to interact with it once it stops and has a green line of text.

If There Are Errors​

If you don’t see the screen below, the import process completed without any errors and you can skip to Step Two: Verify Source Database. If you see the screen below, SSMA failed to bring some of the Data over from Access. If the errors contain text stating that a key column does not allow DBNull.Value, you can click the Attempt Automatic Repair button at the bottom of the window.

info

This can only be done if you have Microsoft Office 2010 or higher installed on this machine. Otherwise, contact Soaring Software Solutions, Inc for help.

When you click the Attempt Automatic Repair button, TCMax® will display a message explaining this process and when you click OK it will attempt to tell Microsoft® Access to Compact and Repair the temporary copy of your Microsoft® Access Database which should remove the records without primary key values. Microsoft® Access will ask you to enter your Database Password. Depending on your operating system and Windows setup you might not see this password input box. If you just see a spinning wheel / wait cursor try hitting Alt + Tab until you find the password input box. It will not be displayed on your taskbar but should look like the image below.

Once the Database Password has been correctly input and you have clicked OK you will see the black command prompt window again. It should stop on the green line of text and you’ll have to enter your password once again.

If you still see the SQL Server Migration Assistant Errors window, contact Soaring Software Solutions, Inc for help.

Step Two - Verify Source Database: Once SSMA has moved all of your old Version 8 Access Data into temporary tables in your new Database you can proceed to Step Two which is Verify Source Database. Clicking the Verify Source Database button will allow TCMax® to verify that the old Microsoft® Access Data is complete and ready to be synchronized. Once this step has completed proceed to Step Three: Sync Data.

Step Three - Sync Data: At this point you can click the Sync Data button to move the Data to your Microsoft SQL Server® Database. During the sync, information will appear on the screen letting you know what step of the process you are on.

Step Four (Optional) - Clear Old Data: You can remove any old Database objects that will no longer be used by TCMax® by clicking the Clear Old Data button.

Migrate Special Options Data​

During the Migration process, a Migrate Special Options Data window will appear. This window is used to let us know how the Data needs to be copied based off of the options you were using in Version 8 of TCMax®.

Select the Shop Code(s) that you would like to run the tool against and click the Migrate button under the Special Options that you were using. Once this is finished you can click the Close button to close this window and return to the Import/Export screen.

note

Regardless of how you have brought new Data into your system, if you did not import information into an already existing/selected shop code you will need to select the newly imported shop code from the Settings > Sites and Shops screen to have visibility of the items.
